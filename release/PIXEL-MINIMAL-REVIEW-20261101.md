## Current design

Exactly TWO new tables in migrations/0009_ad_measurement.sql:

- ad_consents: immutable one-hour account/offer grant, policy version, request idempotency and irreversible revocation. No grant overwrite or automatic deletion.
- ad_purchase_attempts: unique stable event/payment-session and consent reservation, actor hash, eligibility revision, timestamp and SDK enqueue acknowledgment. Reservation starts uncertain BEFORE payload is returned. No reset/delete path; SQL triggers enforce permanence and monotonic acknowledgment. Never label enqueue as delivery.

No Checkout creation, new Stripe API key, Price IDs, Events API, new payment provider or parallel checkout exists. functions/api/stripe-webhook.js restored EXACTLY to preserved2.68.7 baselinefc6deb7; fulfillment and auth are unmodified. Existing Payment Link URLs and campaign references unchanged. SDK/page never loads on app/recipe/auth pages. Existing Kit entry has no effect when public flag is off. Consent UI checkout buttons navigate to existing Kit or homepage pricing; their ordinary membership/purchase checks continue normally.

Receipt proof: current authenticated email -> exact active entitlement session AND payment-intent AND plan/amount/currency -> durable signed paid_orders. Entitlement alone/browser return are not proof. Missing ownership, overwritten older entitlements, other buyer, refund/test/unknown mode, late/expired/withdrawn consent or exclusion all suppress. Consent must predate the recorded Stripe event and remain valid now. Timestamp second granularity can conservatively miss a very rapid purchase; no retrospective backfill. Atomic INSERT rechecks consent, exact ownership and ledger snapshot. Payload is reconstructed; no stored JSON outbox. Same payment has same event hash across grants/reloads, beyond TikTok's48hour dedup window.

This pilot deliberately measures ONLY pre-consented authenticated explicitly eligible customers. Anonymous/unknown customers still purchase normally, but no Purchase is emitted. Account email ownership is not cardholder/legal-person identity, nor proof a particular ad caused a sale. Browser-only blockers, lost returns, expired consent and overwritten current entitlements cause undercount. This is accepted conservative engineering scope, not complete market attribution.
